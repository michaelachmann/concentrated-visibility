# Concentrated Visibility — Notebooks & Reproducibility

This repository contains Jupyter notebooks and supporting data for the dissertation chapter *Concentrated Visibility*, which analyses the face visibility of top political candidates (*Spitzenkandidat:innen*) on Instagram during the 2021 German federal election campaign (*Bundestagswahl*). The analysis covers posts and stories published by five parties (CDU, CSU, SPD, Grüne, FDP) and one front-runner per party during the final two weeks before election day (12–25 September 2021).

> **Note:** Original image files are **not** included in this repository due to copyright restrictions. The `data/` directory contains annotation outputs, model results, and metadata only — no image content.

## Notebooks

The chapter addresses two separate classification tasks, each with its own model comparison and annotation study. The notebooks are organised accordingly. Filenames reflect the date they were created and **do not** indicate execution order.

**Task A — Face Verification (RQ1a):** Is the party's front-runner visible in this image?
Models compared: RetinaFace + FaceNet512 vs. GPT-4o.

**Task B — Person Count (RQ1b):** How many people are in the focus of this image?
Models compared: RetinaFace (face bounding boxes), Google Cloud Vision (object detection), GPT-4o.

For the substantive analysis (RQ2), the human-annotated face identity labels (Task A) are combined with the GPT-4o person count (Task B, best-performing model).

Notebooks in Stages 1–2 require the original image files. Stage 2 additionally requires an OpenAI API key. Stage 3 evaluation notebooks require intermediate files produced by Stages 1–2 (see prerequisites listed in Stage 3 below).

## Getting started

```bash
git clone <repo-url>
cd concentrated-visibility
pip install -r requirements.txt
jupyter notebook
```

Open the notebooks in the order shown in the tables above. Stage 3–4 notebooks run entirely on the files in `data/` without additional setup.

**Hardware:** Stages 1–2 (face detection, GPT-4o) were developed on Google Colab with an NVIDIA T4 GPU (Python 3.10, CUDA 11.8). GPU access is recommended for notebooks 1–7; Stages 3–4 run on CPU.

For Stage 2 notebooks that call GPT-4o, set your OpenAI API key before launching Jupyter:
```bash
export OPENAI_API_KEY=your-key-here
```

Stage 1 and 2 notebooks additionally require the following files (not included due to copyright). Place them in `data/` before running:

**Image archives:**
- `posts.zip` — Instagram post images
- `insta-story-images.zip` — Instagram story images
- `2024-01-03-database-final-v4.zip` — Politician reference face database (avg. 15 images per front-runner)

**Corpus metadata files:**
- `2023-10-12-Image-Master-BTW21.csv` — post corpus metadata (read by nb 4)
- `2023-10-12-Final-Instaloader-Crowdtangle-Merged-w-filenames-and-original-image-filenames-and-faces.csv` — full post metadata (read by nb 9)
- `2023-10-02-Stories-Person-Focus.csv` — story corpus metadata (read by nb 4)
- `images_v2.csv`, `AllFaces-Tasks.csv` — story face data from BA thesis (read by nb 1)
- `2022-10-10-users.csv`, `2023-06-06-CrowdTangle-Final.csv` — account and engagement metadata (read by nb 13)
- `2023-12-06-Reviewed-Faces-Per-Image-Wide.csv` — reviewed story face labels (read by nb 14)

## Data availability & ethics

The structured data in `data/` and the notebook code are released under [CC BY 4.0](LICENSE). The original images cannot be redistributed due to Instagram's Terms of Service and copyright held by the account owners.

**Annotator anonymisation:** Email addresses and names in LabelStudio annotation exports have been replaced with `annotator1`–`annotator7`. Numeric LabelStudio user IDs used as column headers in annotation CSV files are internal identifiers that do not map to personal data in this repository.

**Copyright redaction:** Text fields that could contain copyrighted Instagram content (captions, hashtags, poll questions, mentions) have been cleared from all CSV files.
